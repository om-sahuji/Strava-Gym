# Runs feature — implementation notes

Strava runs inside GymRoutines. Personal, single-user, no ads, no analytics, no new tracking SDKs.

## Phase 0 — Repo findings (read-only)

- **Language / toolkit**: 100 % Kotlin, single `:app` module. UI is **Jetpack Compose** with
  **Material 2** (`androidx.compose.material:1.4.3`).
- **Build**: AGP 8.1.0, Gradle 8.2.1, Kotlin 1.9.0, KSP (Room), JDK 17, compileSdk 33,
  buildTools 34.0.0, minSdk 21, targetSdk 33.
- **DB**: Room 2.5.2, single `AppDatabase` (`workout_routines_database`), was **version 43**, schema
  export enabled into `app/schemas/…AppDatabase/`. Explicit `Migration` objects are registered in
  `di/Modules.kt`, no destructive fallback.
- **DI**: Koin (`di/Modules.kt`): `single` DB, `factory` DAOs/repositories, `viewModel` builders;
  view models obtained in Compose with `org.koin.androidx.compose.getViewModel`.
- **Navigation**: Accompanist animated `NavHost` + `ModalBottomSheetLayout`, routes are
  `enum class Screen` names. Bottom bar (`ui/main/BottomBar.kt`) had 3 tabs
  (Routines / Exercises / Insights).
- **Charting**: hand-drawn Compose `Canvas` (`ui/components/SimpleLineChart.kt`), no chart library.
- **Existing gym data**: `Workout(routineId, startTime, endTime)` + `WorkoutSetGroup` + `WorkoutSet`.
  Settings live in DataStore (`data/Preferences.kt`, `AppPrefs`).

## What was added

**Data layer (phase 1)**
- `data/domain/Run.kt` — new Room entity `run_table` with `stravaId` (PK), `name`,
  `startTimeEpochSec`, `distanceMeters`, `movingTimeSec`, `elapsedTimeSec`, `elevationGainM`,
  `avgHeartRate?`, `summaryPolyline?`, `sportType`; index on `startTimeEpochSec`.
- `data/dao/RunDao.kt` — `upsert` (list + single), `getAllOrderedByDateDesc` (Flow),
  `getRuns`, `getBetween(start, end)`, `getRun`, `deleteAll`.
- `data/AppDatabase.kt` — `version = 44`, `MIGRATION_43_44` (`CREATE TABLE run_table` +
  index). Existing tables untouched; migration is registered in `di/Modules.kt`.
- `data/Repository.kt` — `RunRepository`.
- `app/schemas/…/44.json` — exported schema (generated by Room).
- `androidTest/.../MigrationTest.kt` — `MIGRATION_43_44` added to `migrateAll` plus a
  `migrate43to44` test (compiles; not executed here, no emulator).

**Strava sign-in (phase 2)**
- `data/strava/StravaApi.kt` — OAuth token exchange / refresh and activities fetch over
  `HttpURLConnection`; `StravaResult` (Success / HttpError / NetworkError / NotConfigured /
  NotConnected). No tokens or secrets are ever logged.
- `data/strava/StravaClient.kt` — authorization URL
  (`https://www.strava.com/oauth/mobile/authorize` with
  `redirect_uri=omfit://localhost/strava`, `scope=activity:read_all`), code exchange, automatic
  refresh when the access token expires within 60 s, and one refresh + retry on HTTP 401.
- `data/strava/StravaCredentials.kt` — client id/secret and tokens encrypted with an AES/GCM key
  from the Android Keystore, stored in a private `SharedPreferences` file.
- `data/strava/StravaAuthCallback.kt` + `ui/strava/StravaAuthActivity.kt` — catches the
  `omfit://localhost/strava?code=…` redirect (manifest intent filter), hands the code to the
  settings screen and returns to `MainActivity`.
- `ui/settings/strava/StravaSettings.kt` + `StravaSettingsViewModel.kt` — Settings → **Strava**:
  Client ID / Client Secret fields, "Save", "Connect Strava" (opens the browser), connection
  status, "Disconnect" (clears tokens, keeps imported runs), and the **"Paste code manually"**
  fallback (accepts the bare `code=` value or a full redirect URL).
- `AndroidManifest.xml` — `INTERNET` permission and the `StravaAuthActivity` intent filter.

**Sync (phase 3)**
- `data/strava/StravaModels.kt` — `@Serializable` DTOs and `StravaMapper`, which keeps only
  `Run`/`TrailRun`/`VirtualRun` (using `sport_type`, falling back to `type`), parses the ISO
  `start_date` to epoch seconds and maps every field including `map.summary_polyline`.
- `data/strava/StravaSyncer.kt` — paginates `GET /athlete/activities?per_page=100&page=N` until an
  empty/short page, upserts runs by `stravaId`, stops on 429 with a "rate limit" message, keeps
  local data on network errors, stores `lastSyncEpoch` in DataStore and syncs incrementally with
  `after`. `syncIfStale()` syncs when the last success is older than 30 minutes.
- **Trigger**: `GymRoutinesApplication` calls `syncIfStale()` on app start (background coroutine),
  the Runs screen re-checks on resume, and its toolbar has a manual refresh button.
- Tests: `StravaMapperTest`, `RunFormatTest`, `RunStatsTest`, `PolylineDecoderTest` (22 tests).

**Runs UI (phase 4)**
- `ui/main/BottomBar.kt` — new **Runs** tab (4th, `Icons.Default.DirectionsRun`).
- `ui/runs/Runs.kt` + `RunsViewModel.kt` — newest-first list (date, name, km with 2 decimals,
  duration, pace in min/km, avg HR when present), weekly bar chart on top drawn with Compose
  `Canvas` (this week + previous 4 weeks), last-sync line, sync messages, and an empty state that
  offers "Connect Strava" when not connected.
- `ui/runs/RunDetail.kt` + `RunDetailViewModel.kt` — all fields, plus the route drawn as a simple
  `Canvas` path from the decoded `summary_polyline` (no Google Maps SDK, no API key).
- `util/RunFormatUtil.kt`, `util/RunStats.kt`, `util/PolylineDecoder.kt` — pure Kotlin helpers
  (tested).
- Strings added to `app/src/main/res/values/strings.xml` only (other locales fall back to English).

## Decisions

- **Navigation**: a 4th bottom tab ("Runs") next to the existing three, and a Strava entry in the
  existing Settings screen — no changes to the existing tabs' behaviour.
- **No new dependencies**: `HttpURLConnection` + `kotlinx.serialization` (already used by Room
  `Converters`) for the API, Compose `Canvas` for both charts, and Keystore AES/GCM instead of
  `androidx.security:security-crypto` for the secrets.
- **Secret storage**: own small AES/GCM wrapper over a Keystore key. On API 21/22 (Keystore has no
  AES) values are only base64-encoded — see limitations.
- **Incremental sync** asks Strava for `after = lastSync - 7 days`; the upsert by `stravaId` makes
  the overlap harmless and catches activities uploaded late.
- **First sync** omits `after`, i.e. imports the full history page by page.
- **No calendar marking**: the gym app's "history" (`Insights`) is a plain list of workouts, not a
  date/calendar grid. Marking days there was the lowest-priority item and was skipped on purpose to
  keep the existing screen untouched.

## How to set up Strava

1. Go to <https://www.strava.com/settings/api> and create an API application.
2. Set **"Authorization Callback Domain"** to `localhost` (the app redirects to
   `omfit://localhost/strava`; Strava only needs the domain part).
3. In the app: **Settings → Strava**, paste the **Client ID** and **Client Secret**, tap **Save**,
   then **Connect Strava**. Sign in and approve `activity:read_all`.
4. If the browser does not return to the app, copy the `code=…` value from the address bar, paste it
   into **"Paste code manually"** and tap **Exchange code**.
5. Open the **Runs** tab and press refresh; the first sync imports your full run history.

Client ID/Secret/tokens stay on the device (encrypted) and are never committed, logged or sent
anywhere except to strava.com.

## Known limitations

- **API 21/22**: the Android Keystore cannot hold AES keys before API 23, so on those devices the
  client secret/refresh token are stored base64-encoded rather than encrypted.
- Only *running* activity types are imported (`Run`, `TrailRun`, `VirtualRun`); rides, swims, etc.
  are ignored by design.
- Deleting a run on Strava does not remove it from the app (the app only upserts); `RunDao.deleteAll`
  exists for a future "clear runs" action, which is not exposed in the UI.
- The route is a simplified summary polyline drawn without a map background; no map tiles, no GPS
  detail, no splits/streams.
- Sync is a simple one-shot pagination loop (no WorkManager): it runs on app start when stale, on
  Runs-screen resume, and on manual refresh. A very long history on a bad connection can take a
  while; already-synced runs are kept.
- **Pre-existing issue (not caused by this change)**: `app/src/test/.../DateUtilTest.kt` does not
  compile against `main` — it references `currentDailyStreak()` and `kotlin.time.hours`, which
  commit b69fc312 ("Remove obsolete DateUtil functions") removed. The CircleCI job only runs
  `assembleDebug`, so nobody noticed. The new unit tests were verified by temporarily moving that
  one file aside; the file itself was left untouched. `./gradlew testDebugUnitTest` will fail to
  compile the test source set until that obsolete test is deleted (recommended separate cleanup
  commit).
- Not verified on a device/emulator here (no Android device in this environment): the OAuth
  redirect, the live Strava API calls and the rendered UI were not exercised at runtime. Verified
  instead: `assembleDebug` from clean, `compileDebugAndroidTestKotlin`, and the 22 JVM unit tests.

## Build environment (this sandbox)

No JDK/Android SDK pre-installed and no root. Toolchain installed under `$HOME/tools`:
Temurin JDK 17 + Android `cmdline-tools` with `platforms;android-33` and `build-tools;34.0.0`.
`local.properties` (git-ignored) points at that SDK.

```bash
export JAVA_HOME=$HOME/tools/jdk-17.0.21+9
export ANDROID_SDK_ROOT=$HOME/tools/android-sdk
./gradlew assembleDebug -Dorg.gradle.jvmargs="-Xmx1400m -XX:MaxMetaspaceSize=512m"
```

Deliverable APK: `dist/app-debug.apk` (copied from `app/build/outputs/apk/debug/app-debug.apk`).
It is not committed because the repository's `.gitignore` excludes `*.apk`.
